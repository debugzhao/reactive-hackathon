# 🔀 练习 B：动态订阅（DynamicWatcher）

> 任务：合约在运行中根据收到的事件增加或取消订阅（例如收到「停止」事件后取消订阅）。
> 提交：① 合约地址和至少两次触发的交易链接；② 一段说明：如何防止它无限执行或耗尽余额。

## 🎯 一句话

Base Sepolia 上的 `Switchboard` 发出 `Start(target, limit)`，Lasna 上的 `DynamicWatcher` 就在 `react()` 里**订阅** target 的 `Ping`；收到 `Stop(target)` 或处理满 `limit` 条 Ping，就在 `react()` 里**退订**。

```
Base Sepolia                        Lasna DynamicWatcher.react()
Switchboard.start(target, 3) ──▶  SYSTEM.subscribe(target, Ping)        emit Watching
target.ping(1)               ──▶  计数，remaining 3 → 2                  emit PingSeen
target.ping(2)               ──▶  计数，remaining 2 → 1                  emit PingSeen
Switchboard.stop(target)     ──▶  SYSTEM.unsubscribe(target, Ping)      emit Unwatched(reason=1)
target.ping(3)               ──✗  已退订，Lasna 上不再有 react
```

| 文件 | 作用 |
|---|---|
| [`starter/src/Switchboard.sol`](../starter/src/Switchboard.sol) | 源链控制台，只有 owner 能发 Start / Stop |
| [`starter/src/DynamicWatcher.sol`](../starter/src/DynamicWatcher.sol) | Reactive 合约：构造时只订阅控制通道，运行中按事件增减订阅 |
| [`starter/test/DynamicWatcher.t.sol`](../starter/test/DynamicWatcher.t.sol) | 17 个测试。用「退订参数对不上就不生效」的严格 Mock 验证订阅和退订一一对应 |
| [`starter/script/DynamicSub.s.sol`](../starter/script/DynamicSub.s.sol) | 部署和触发脚本 |
| [`starter/script/dynamic-status.sh`](../starter/script/dynamic-status.sh) | 核验：打印合约状态，以及每次 react 的 Lasna 交易和对应的源链交易 |

> 💡 Omni 是单一执行环境，`react()` 里可以**直接**调用 `SYSTEM.subscribe` / `unsubscribe`。旧版 ReactVM 需要绕一圈回调，现在不需要了。

## 🖥️ 操作步骤

**准备**：Base Sepolia 至少 0.001 ETH（当前 0.035）；Lasna 至少 0.3 lREACT（当前 0.41，够跑一轮；想多跑几次就再换一些）。

```bash
cd ~/repo/web3/reactive-hackathon/starter
forge test --match-contract DynamicWatcher    # 17 passed
set -a; source .env; set +a                   # .env 里已经加好练习 B 的变量
```

**① 源链部署 Switchboard 和 target**

```bash
forge script script/DynamicSub.s.sol:DeployDynOrigin --rpc-url $DYN_ORIGIN_RPC_URL --broadcast
```

把输出的 `SWITCHBOARD_ADDR`、`TARGET_ADDR` 填进 `.env`，然后重新 `source`。

**② Lasna 部署 DynamicWatcher**（预付 0.1 lREACT）

```bash
DYN_FUND=100000000000000000 forge script script/DynamicSub.s.sol:DeployDynWatcher \
  --rpc-url $LASNA_RPC_URL --broadcast --with-gas-price 100gwei
```

> ⚠️ 一定要加 `--with-gas-price 100gwei`。不加的话 forge 按 200 gwei 估算，会要求账户有 0.48 lREACT，余额不够，交易会被拒。

把输出的 `WATCHER_ADDR` 填进 `.env`，然后重新 `source`。

**③ 触发：开始监听** → 等 5–10 秒

```bash
forge script script/DynamicSub.s.sol:DynStart --rpc-url $DYN_ORIGIN_RPC_URL --broadcast   # 默认 limit=3
bash script/dynamic-status.sh   # 预期：targets() 有 target，remaining=3，出现一条 Watching
```

**④ 触发：发两次 Ping**

```bash
forge script script/DynamicSub.s.sol:DynPing --rpc-url $DYN_ORIGIN_RPC_URL --broadcast
forge script script/DynamicSub.s.sol:DynPing --rpc-url $DYN_ORIGIN_RPC_URL --broadcast
bash script/dynamic-status.sh   # 预期：seen=2，remaining=1，出现两条 PingSeen
```

**⑤ 触发：停止监听**

```bash
forge script script/DynamicSub.s.sol:DynStop --rpc-url $DYN_ORIGIN_RPC_URL --broadcast
bash script/dynamic-status.sh   # 预期：targets() 为空，remaining=0，出现 Unwatched
```

**⑥ 反向证明：退订后再 Ping 一次**

```bash
forge script script/DynamicSub.s.sol:DynPing --rpc-url $DYN_ORIGIN_RPC_URL --broadcast
bash script/dynamic-status.sh   # 预期：reactCount 不变，没有新的 PingSeen
```

**（可选）⑦ 次数用完自动退订**：`DYN_LIMIT=1` 再跑一次 ③，然后跑一次 ④，会看到 `Unwatched`，reason=2。

> 每次 react 大约花 0.015–0.03 lREACT，③–⑤ 一共 4 次 react。如果 `dynamic-status.sh` 显示 debt > 0，先充值再用 `coverDebt()` 还清欠费，否则合约会静默停止。

| 5 | Ping（退订后） | 无 | 证明退订已生效 |

**如何防止无限执行或耗尽余额**

DynamicWatcher 从三个层面限制花费：

1. **控制通道有权限**。只有 Switchboard 的 owner 能发 Start / Stop。Watcher 只接受来自 Switchboard 地址、并且来自指定链 ID 的控制事件，其他合约发出同签名的事件会被忽略。
2. **订阅数量有上限**。最多同时监听 3 个 target（`MAX_TARGETS`）。重复的 Start 会被忽略。`target = address(0)` 会被拒绝，因为它会变成「订阅整条链上所有合约的 Ping」，费用无法控制。
3. **每个订阅的处理次数有上限**。`limit` 最大为 10（`MAX_LIMIT`）。处理满 limit 条后，在 `react()` 里自动退订；退订前已经在路上的事件直接 `return`，不计数。

另外还有几道兜底：

- **不会自我循环**。Watcher 不发回调，它自己发出的事件也不在订阅范围内，所以不存在「执行 → 产生事件 → 再次触发自己」的循环。
- **过滤一律用 `return`**，不用 `revert`，因为 revert 照样收费。
- **总预算有上限**。部署时只预付 0.1 lREACT，花完就产生欠费，网络会停止投递，不会继续扣钱包里的钱。owner 可以用 `stopAll()` 一键退订所有 target 和控制通道；合约还暴露了 `coverDebt()` 和 `resumeControl()`，用于还清欠费后恢复运行。

在最坏情况下，一次 Start 最多带来 3 × 10 = 30 次数据事件的 react，再加上 owner 自己发的控制事件。
